## 步驟 2｜分類方案

### 建議：前台用白話系列，後台以 PESTLE 標籤策展

不建議前台直接展示 PESTLE 六類。這是編輯選題框架，觀眾更容易按生活問題找到內容。也不建議用每一篇獨立的煽情式問句當系列名稱，否則 100 篇會碎成很多小分類。建議保留現有 3 類，新增 5 個清楚、可擴充的分類：

| 前台分類 | 範圍 |
|---|---|
| 投資詐騙與平台風險（既有） | 詐騙手法、平台／託管／交易對手風險 |
| 金融史與市場週期（既有） | 歷史危機、泡沫、週期與市場機制 |
| 黃金與總體經濟（既有） | 黃金、貨幣、通膨、利率、美元與總體數據 |
| 世界政策與市場 | 政策、地緣政治、貿易與市場傳導 |
| 家庭世代與生活成本 | 人口、住房、照護、退休與家庭財務選擇 |
| 科技工作與收入 | AI、數位資產基礎、工作變化、技能與收入來源 |
| 跨境資產與法律 | 跨境買房／持有資產、稅務、法規與消費者保障 |
| 氣候能源與生活風險 | 極端天氣、能源、保險、供應鏈與居住風險 |

資料仍沿用 `category`；另在每篇編輯中繼資料放 PESTLE 主標籤（可多標，但一個主標籤）與來源／時效欄位。既有 JSON schema 暫不擴欄，待擁有者確認後再依實際實作需要決定如何承載中繼資料。

**不同意之處與取捨：**不同意把 PESTLE 六字直接當觀眾分類；也不把人口老化／少子化都簡化成房價預測。人口題應呈現照護、勞動、財政、家庭分工等多條影響路徑。詐騙若屬金融平台與投資承諾，放 Ken 既有反詐分類；若屬感情交友或長者數位安全，留在相應的 Alice 系列，避免品牌內容重複與混淆。

## 100 篇題目提案

PESTLE：P 政治、E 經濟、S 社會、T 科技、L 法律、Env 環境。時效性「低」表示可做常青概念篇；「中」表示政策／制度會更新、需標查閱日期；「高」表示依即時發布或事件，宜在發布前重查。來源為候選一手來源機構；逐篇的確切文件、數字、日期與連結留待下一階段核實。
